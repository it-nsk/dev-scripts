# Архитектура и состав пакета

Репозиторий содержит два независимых инструмента:

- Composer-пакет `it-nsk/dev-tools` запускает PHP CS Fixer, PHPStan и
  устанавливает pre-commit hook;
- глобальный POSIX-совместимый CLI `bgt-dev` управляет первичным развёртыванием,
  Docker Compose и локальными дампами до появления `vendor`.

Глобальный CLI не использует PHP и Composer, поэтому bootstrap не образует
циклическую зависимость.

## Исполняемый код

- `bin/dev-tools` — Composer binary. Подключает autoload и передаёт аргументы в
  `Cli`.
- `bin/bgt-dev` — глобальный shell CLI: Docker lifecycle, dump, длинные команды
  внутри контейнера и `self-update`.
- `install.sh` — одноразовая установка `bgt-dev` в `/usr/local/bin`.
- `src/Cli.php` — список доступных команд, разбор `--config`/`--mode`, поиск
  корня проекта и запуск нужного модуля. Чтобы добавить новую команду, нужно
  добавить её класс и одну ветку в `match`.
- `src/Config.php` — читает `.dev-tools.yaml`, проверяет типы значений и строит
  команды `docker compose exec`.
- `src/Process.php` — запускает внешние команды массивом аргументов через
  `proc_open`, без `eval` и сборки shell-строк.
- `src/CsFixer.php` — `cs:check`, `cs:fix` и форматирование staged PHP-файлов.
- `src/PhpStan.php` — формирует и запускает команду PHPStan.
- `src/Hooks.php` — копирует pre-commit hook в `.git/hooks` и формирует local
  либо Docker-команду для него.

## Общие настройки и интеграция

- `config/php-cs-fixer.php` — единый набор правил PHP CS Fixer; список каталогов
  берётся из `.dev-tools.yaml` проекта.
- `config/phpstan.neon` — общие настройки PHPStan и расширения для Symfony и
  Doctrine.
- `hooks/pre-commit` — короткий шаблон hook. При установке placeholder команды
  заменяется на local или Docker-вызов.
- `make/dev-tools.mk` — необязательные Make-цели, которые делегируют работу
  `vendor/bin/dev-tools`.
- `.dev-tools.yaml.dist` — пример всех поддерживаемых проектных настроек.

## Метаданные и документация

- `composer.json` — имя пакета, PHP-зависимости, PSR-4 autoload, binary и
  тестовые scripts.
- `composer.lock` — точные версии зависимостей для разработки самого пакета.
  Проекты-потребители используют собственный lock-файл.
- `README.md` — краткое подключение и основные команды.
- `docs/quality-tools.md` — подробная интеграция и проверка в другом проекте.
- `LICENSE` — лицензия MIT.
- `.gitignore` — исключает vendor, кеши анализаторов, IDE и собранные файлы.

## Тесты

- `tests/e2e.sh` — создаёт временный Git/Composer-проект и проверяет local fixer,
  PHPStan и hook.
- `tests/docker-e2e.sh` — та же проверка через настоящий PHP 8.3 контейнер.
- `tests/project/` — один общий минимальный Composer-проект с двумя намеренно
  неформатированными PHP-файлами, local/Docker YAML-конфигами, Dockerfile и
  Compose. После Docker-теста контейнер, сеть, image и временный проект удаляются.

Тестовые проекты не являются частью установленного runtime: Composer-пакет
использует из них только исходники, попавшие в архив, но они не подключаются
autoload и не выполняются у потребителя.

## База данных

Composer-часть не подключается к БД. Глобальный `bgt-dev` умеет скачать gzip
dump по SSH и импортировать его в локальный MySQL-сервис Docker Compose.
Источник, имя файла, сервис, база и реквизиты задаются переменными `BGT_*`
проекта. В бинарнике нет адресов или названий конкретных проектов.

Зависимость `phpstan/phpstan-doctrine` нужна исключительно для статического
анализа Doctrine entities/repositories в Symfony-проектах. Она анализирует PHP
код и metadata и не устанавливает соединение с рабочей базой при обычном
запуске общей конфигурации.

## Добавление новой функции

Например, для Rector:

1. создать `src/Rector.php` с формированием и запуском команды;
2. добавить одну ветку `'rector' => ...` в `src/Cli.php`;
3. при необходимости добавить секцию `rector` в `.dev-tools.yaml.dist`;
4. добавить Make-цель и сценарий в E2E.

Промежуточные `Context`, `Arguments`, `Command` и отдельная регистрация сервисов
для этого не нужны.
